# Cobblemon Dynamics 2.0: shared pastures, terrain spots, progression, Sentry and the Pasture Shelf

> Read this plan first, then execute only the task assigned to your branch. Steps use checkbox (`- [ ]`) syntax for
> tracking.

**Goal:** Ship Cobblemon Dynamics 2.0.0. Pastures become cooperative across teammates and pastured contributors with an
optional Access Lock, offline-safe `tethering` ownership, cooperative land-claim checks, and opportunistic dual-type
Fairy auto-assignment (`TEAM`). Workers stand on carpets, paths, slabs, leaves, snow layers and Cobblemon placeables,
see past floor trim via `VoxelShape` ray clipping, gain body-width and Alpha interaction reach, and stay anchored in
their `workArea` with distance-scaled travel timeouts and progressive retry backoff (`NAV`). Shiny, Alpha, Majestic
(`Cobblemon Majesty` with zero jar dependency), Move Mastery, Mate and rarity bonuses stack multiplicatively alongside
the Nature-, bed- and Friendship-driven `Slacking` (`"Slacking Off..."`) state and uncapped EV-free Work XP and passive
Friendship (`PRG`). Dark-types guard the `workArea` as Sentries with nocturnal
stamina efficiency while Fire-types stoke Cobblemon Campfire Pots (`SNT`). A fold-out Pasture Shelf, persistent 3D
`workArea` wireframe, synced `IdleReason` and trait badges, and optional Jade (`15.10.6`) tooltips make every pasture and
worker state legible (`SHF`).

**Architecture:** Five build slices (`2B` through `2F`) run in two clean waves so every branch compiles and passes
`./gradlew build` standalone with zero duplicate stubs: Wave 1 branches `2B` (`TEAM`), `2C` (`NAV`), `2D` (`PRG`), and `2E`
(`SNT`) in parallel from `v20-design` (`2A`), Wave 2 branches `2F` (`SHF`) after `2B` and `2D` merge to `main` (consuming
real `WorkModeData.locked`, `PastureAccessPolicy`, `WorkerStatus.SLACKING`, and `WorkTraits`), and Wave 3 (`2G`) merges
all slices and runs the full 2.0.0 gate. Pure domain decisions — access policy, surface heights, reach math, zone tether,
trait multipliers, slack probabilities, XP/Friendship clocks, Sentry spawn predicates, Campfire Pot ticks, shelf state and
Jade line formatting — live in plain Kotlin objects with unit tests that need no Minecraft runtime. Optional mod classes
(`FTBTeamsAPI`, `OpenPACServerAPI`, `Jade`) stay strictly inside `compat/<modid>/` behind `ModList.isLoaded`.

**Tech Stack:** Minecraft 1.21.1, NeoForge 21.1.265 (`[21.1.219,)`), Cobblemon 1.8.4 (`[1.8.4,1.9)`), Kotlin for Forge
5.10 (`[5.10,)`), Create 6.0.10 (optional), AE2 19.2.19 (optional), FTB Chunks 2101.1.23 + FTB Teams 2101.1.12
(optional), Open Parties and Claims 0.33.0 (optional), MineColonies 1.1.1420 (optional), and Jade `15.10.6` (`compileOnly`
from Modrinth maven, optional). `Cobblemon Majesty` requires zero jar dependency.

**Spec:** The [spec sheet](2026-11-09-v1-spec-sheet.md): the new 2.0 areas `TEAM` (`CD-TEAM-01` to `CD-TEAM-11`), `NAV`
(`CD-NAV-01` to `CD-NAV-10`), `PRG` (`CD-PRG-01` to `CD-PRG-16`), `SNT` (`CD-SNT-01` to `CD-SNT-07`), and `SHF`
(`CD-SHF-01` to `CD-SHF-10`), the gate row `CD-REL-20`, and the 2.0 parts of the rows in
[Rows of earlier releases with a 2.0 part](#rows-of-earlier-releases-with-a-20-part). Input `R97` holds the approver's
2026-11-28 rulings, and [ADR-0021](../adr/0021-shared-pastures-and-team-access.md),
[ADR-0022](../adr/0022-surface-spots-voxel-sight-and-zone-tether.md),
[ADR-0023](../adr/0023-variant-mastery-mate-and-work-progression.md), and
[ADR-0024](../adr/0024-dark-sentry-pasture-shelf-and-jade.md) record the design. Every 2.0 row is `agreed` under `R97`. If
this plan and the spec sheet disagree, the spec sheet wins.

## Global constraints

- **Explicitly ruled out (`R97`):** Auto-depositing farm or tree drops into chests touching a pasture (rejected so the
  Steel-type `Magnet` keeps its full purpose), new workstation, feed-trough or job-board blocks (kept minimal in the
  Pasture Shelf UI), and Effort Values from working (`0` EVs on all Work XP).
- **Silence (`SilenceTest`):** Work and Sentry effects play zero sound. Do not name `destroyBlock`, `levelEvent`,
  `playSound`, `useWithoutItem`, `useItemOn`, `attemptShear`, `BreakEvent` or `FakePlayer` in KDoc or comments of scanned
  packages.
- **Compat isolation (`CompatImportsTest`, `verifyJar`):** Store optional mod package prefixes as slash paths (`snownee/jade/`)
  in `OptionalMods.kt` and `build.gradle`, never dotted package strings in `src/main`. Never touch optional mod classes
  in `object` initializers or top-level properties.
- **Shared files:** Keep edits to `CobblemonDynamics.kt`, `ServerConfig.kt`, `EngineSettings.kt`, `WorkEngine.kt`,
  `OptionalMods.kt`, `neoforge.mods.toml`, `en_us.json`, `ARCHITECTURE.md` and count-based tests (`LoadLinesTest`,
  `BuiltInRoleFilesTest`, `PlayerGuideTest`, `scripts/testpack/testpack.py`) small and additive.
- **Client testing (`R93`):** Never launch `runClient` or the test pack's `client` case. Client/UI confidence comes from
  unit tests of layout, state and codecs plus code inspection.

## How to execute this plan

1. **Branches and wave DAG.**
   - **Wave 1** forks four parallel branches from `v20-design` (`2A`):
     - `2B` (`v20-team-claims`): Task 1 (`TEAM`)
     - `2C` (`v20-terrain-tether`): Task 2 (`NAV`)
     - `2D` (`v20-progression`): Task 3 (`PRG`)
     - `2E` (`v20-sentry-pot`): Task 4 (`SNT`)
   - **Wave 2** forks `2F` (`v20-shelf-jade`, Task 5 `SHF`) after `2B` and `2D` merge to `main` so `2F` consumes the real
     `WorkModeData.locked`, `PastureAccessPolicy`, `WorkerStatus.SLACKING`, and `WorkTraits` with zero duplicate stubs.
   - **Wave 3** (`2G`, `v20-gate`, Task 6) merges all five slices, resolves shared-file seams, and runs the full 2.0.0
     gate.
2. **Test first.** Write failing unit tests first, confirm the expected failure, implement, run unit tests + `ktlint` +
   `build` + `runGameTestServer` through the shared runner `v12-run.sh`, and commit with explicit file paths and `[rag:N]`.
3. **Verify APIs with `javap`.** Check Cobblemon 1.8.4, FTB Teams, OPAC and Jade 15.10.6 signatures with `javap` before
   coding against them.
4. **Coverage.** After any plan edit, `py scripts/check_plan_coverage.py --phase <p>` must exit `0` (`missing: 0`) for
   all eight phases: `1`, `2`, `3`, `1.1`, `1.2`, `1.2.1`, `1.2.2` and `2.0`.
