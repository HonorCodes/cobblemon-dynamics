# Cobblemon Dynamics 1.2.2: the fixes of the cross-feature audit

An independent audit of 1.2.1, which runs on the players' server, found eleven defects across the features. The coordinator ruled
on each finding on 2026-11-22, under the approver's delegation (R81). This plan records the fixes. The plan
`2026-11-22-v1.2.2-hardening.md` of the other 1.2.2 branch fixes the wide workers at the pasture block.

## Global constraints

- No change of the save format. The bindings, the leash index and the claims save as in 1.2.1.
- Each fix of plain Kotlin logic has a unit test. A GameTest covers the behaviour against the real game where the finding asks for one.
- The changes to `WorkEngine.free` are the ones that findings 7 and 8 need, so that the other branch merges cleanly.
- `scripts/check_plan_coverage.py --phase 1.2.2` selects the rows of this plan (`V122_AUDIT_ROWS`, `V122_AUDIT_PARTS`).

## The rulings

| Finding | Ruling |
|---|---|
| 1 | Never clear a binding unless the Pokémon was read and every chunk that the decision reads is loaded. An unknown answer keeps the binding, is not cached, and is asked again later. |
| 2 | The sapling corner is the corner of exactly one complete square, so it is a fixed point. The move runs as a migration only, and never onto a cell that another exclusive binding of the lane reserves. |
| 3 | The areas leave out `#dynamictrees:rooty_soil` and `#dynamictrees:saplings`. |
| 4 | The net sets the rest spot of a resting worker that it moves. A sleeper whose body the tree reaches gives up its bed claim and rests in place. |
| 5 | The switch caches expire after 200 ticks. |
| 6 | The Standby switch passes the bound role as the role whose switch roles count. |
| 7 | The net's flood passes the natural leaves and the trunk of the tree that changed only. |
| 8 | `freeAround` and `drainGrowths` run inside a `try` that logs once. |
| 9 | Each replant cell plants in its own `try`, so no drop is lost. |
| 10 | Accepted as it is: the Picker's extra scans. |
| 11 | `LeashResets` forgets its caches at `ServerStoppedEvent`. |

### Task 1: Bindings on partial information (finding 1)

**Rows:** CD-LSH-35 (new), CD-LSH-31 (amended).

- [x] `TargetHandler.switchAnswer` answers true, false or null (unknown). The default reads `bindRefusal` and `stillValid`.
  `LumberjackHandler.switchAnswer` answers null when the tree search read a cell of a chunk that is not loaded
  (`TreeFactsReader.metUnloaded`).
- [x] `RoleSwitch.rolesOrUnknown` and `RoleSwitch.holdsOrUnknown` make the switch roles and the hold unknown when one answer is
  unknown. `switchRolesOn` returns null while a column of the target or of its 8 neighbours is not loaded (`neighboursLoaded`).
- [x] `LeashResets.check` reads the Pokémon from its pasture, or with `find` from the owner's PC or party while the pasture is not
  loaded (Task C, Step 7 of the 1.2.1 plan). It clears the binding on a false answer only.
- [x] Unit tests in `RoleSwitchTest`: the unknown path of the switch roles and of the hold, and an unknown answer that the cache does
  not hold.

**Deviation.** The ruling says "the pasture was read". The check also reads the Pokémon by `find` while the pasture is not loaded, as
the ruling's second point and the plan's Task C, Step 7 say. An answer from a Pokémon that `find` gives clears a binding only when
every chunk that the decision reads is loaded. CD-LSH-08 checks an entry whose target alone is loaded, so a broken target still clears.

### Task 2: The sapling corner (findings 2 and 11)

**Rows:** CD-LSH-36 (new), CD-CUL-13 (amended).

- [x] `SaplingRules.corner` gives the corner of the one complete square that holds the sapling, or the sapling when none or more than
  one does (`SaplingRules.onlySquare`). The corner resolves to itself. The Lumberjack (`TreeRules.canonical`) and the Cultivator ask the
  same rule, so a Bug/Ground Lumberjack whose replanted base lies in a row 2 wide still grows its own tree.
- [x] `CultivatorHandler.isPartOfTarget` counts the square of a corner only when that square is the corner's only one.
- [x] `LeashResets` moves a binding once per server run, at its first check (`migrated`, in memory). It leaves the binding on its cell
  when an exclusive binding of another Pokémon in the same lane reserves the corner.
- [x] Finding 11: `LeashResets.reset` clears the switch answers and the migration set at `ServerStoppedEvent`.
- [x] Unit tests: `SaplingRulesTest` (the fixed point over rows, fields, an L and a checkerboard; the 3 × 2 case), `TreeRulesTest`.
- [x] GameTest `LeashResetTests.cdLsh36OldBindingsInARowOfSaplingsNeitherWalkNorMerge`: two bindings of 1.2.0 in a row of saplings
  2 wide.

### Task 3: Dynamic Trees in the areas (finding 3)

**Rows:** CD-CRP-24 (amended).

- [x] `FarmingTags.AREA_LEFT_OUT` holds `#minecraft:saplings`, `#dynamictrees:saplings` and `#dynamictrees:rooty_soil`
  (`FarmingTags.ROOTY_SOIL`, moved from `HarvestApply`). The Cultivator's `areaCrop` and the Harvester's `ripeCrop` skip them.
  The Harvester reaches them only when a pack adds them to its tag, and the check costs one tag test.
- [x] Unit test in `FarmingTagFilesTest`.

### Task 4: The safety net (findings 4, 7 and 8)

**Rows:** CD-ASG-28 (new), CD-ASG-25 (amended).

- [x] Finding 4: `freeSlot` sets `restSpot` of a worker in RestingInPlace that it moved. A sleeper whose body overlaps a block gives up
  its bed claim and goes to RestingInPlace at its new place, through the machine's lost-bed path.
- [x] Finding 7: `free` takes the base of the tree that changed. Its flood passes cells with no collision, natural leaves, and the logs
  and mangrove roots of the trunk joined to that base (`TreeWay`). A cabin wall of logs or a hedge of placed leaves stops it.
- [x] Finding 8: `freeAround` and `drainGrowths` run inside `safely`, which catches `Exception` and `LinkageError` and logs once, as
  `freeSlot` did.
- [x] Unit tests in `TreeWayTest`.
- [x] GameTest `GrowthSpotTests.cdAsg28ARestingWorkerStaysOutOfTheTreeThatGrewOnIt`. The sleeper's path has no GameTest: its bed
  release uses the same machine path as the broken bed of CD-BED-11, which has one.

### Task 5: The switch caches and the Standby switch (findings 5 and 6)

**Rows:** CD-LSH-31, CD-LSH-30.

- [x] Finding 5: `SwitchCache` computes again when its key changes or after `SwitchCache.LIFETIME_TICKS` (200), at one computation per
  200 ticks for each worker or binding. A neighbourhood hash would cost a read of each cell that the Lumberjack's search reads.
- [x] Finding 6: `switchInStandby` passes the bound role as `own` and the claimed role as `current` to `switchFor`.
- [x] Unit test in `RoleSwitchTest`: the cache expires after 200 ticks.

### Task 6: The replant (finding 9)

**Rows:** CD-LUM-29 (amended).

- [x] `LumberjackHandler.end` plants each replant cell in its own `try`. A cell counts as planted when it holds the sapling after a
  throw. The drops lose only the held saplings that the planted cells used (`ReplantRule.Replant.takenFor`), and then pop.
- [x] Unit test in `ReplantRuleTest`.
